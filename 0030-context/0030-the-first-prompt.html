9  The first prompt

The microsoft-docs skill gives the agent a way to look things up. The backend skeleton skills describe the project, and AGENTS.md tells the agent when to read each one. Now find out whether the skills and AGENTS.md are enough. Start pi in ~/work and paste this prompt:

Set up the backend skeleton for a small web application in this folder.

- One solution with an ASP.NET Core Web API project and an xUnit test project.
- Add an `Add` operation for two numbers, and a unit test for it.
- Add an API endpoint in its own file that calls `Add` and returns the result.
- In launchSettings.json, set applicationUrl to http://0.0.0.0:5074 so the API
  listens on all interfaces. The browser runs on the host, outside the container.

Finally: git init, write a sensible .gitignore, add everything, and commit.

9.1 What the prompt leaves out

The prompt specifies no file layout and no csproj contents. It contains no code and no command lines. It says nothing about .NET versions or idioms. The prompt states the goal and nothing else. The agent works out the rest.

That split is the point. Prompts describe the task, and the harness describes the rules. A rule you put in a prompt applies to one turn. A rule you put in AGENTS.md applies to every turn for the rest of the project.

9.2 Watch it work

Watch the terminal for this run, because you will see the agent consult the docs instead of guessing. You should see the agent do most of this:

  • run npx @microsoft/learn-cli search ... for .slnx files, then for extension blocks and Minimal APIs
  • run dotnet new and dotnet build, then dotnet test
  • check package versions against NuGet
  • possibly start the API and call it with curl

Nobody told the agent about the dotnet new sln --format slnx flag. Nobody showed it what a C# 14 extension(...) block looks like. It read the documentation because AGENTS.md told it to load the microsoft-docs skill. That skill showed it how to query the docs.
