2  Your toolkit

2.1 The pi agent

The coding agent for this course is pi, an open source agent you run in a terminal. It is deliberately minimal. Out of the box it reads and writes files, edits them, and runs shell commands. That is close to the whole list. Anything beyond that, you add yourself through skills, extensions, and configuration.

That minimalism is exactly why the course uses pi. In a bigger agent, half the harness is already there, hidden behind a settings screen. You never find out what it does or why. With pi, you add every rule the agent follows and every check it has to survive yourself. All of it lives in a file you can open.

2.2 The model: GPT-6 Luna through Novedu

Behind pi sits the model that does the actual thinking. In this course, that model is GPT-6 Luna from OpenAI. Luna is the fast, low-cost model of the GPT-6 series, one step below GPT-6 Sol. Your school’s Novedu platform passes every request from pi on to OpenRouter, a service that sells access to models from many vendors through one account.

Be clear about the trade-off. Out in industry, engineers run stronger models inside far more capable harnesses. The models include Opus, Fable, GPT-6 Sol, DeepSeek, and Kimi. The harnesses include Claude Code, OpenAI Codex, and Cursor. Those combinations take on work packages far bigger than the steps in this course: a refactoring across 40 files, a migration to a new framework version, a bug report with only a stack trace. When you judge what agentic engineering can do, judge it by those, not by the setup in your container.

2.3 Why a low-cost model is good for learning

Your key costs you nothing. Every request still costs your school money, because OpenRouter bills the school for each token Luna reads and each token it writes, its thinking included.

Cut the work into small steps anyway. A task cut into pieces the agent can finish in one turn is easier to check, and cutting work into those pieces is the skill this course trains. A capable model lets you skip that practice. It absorbs a sloppy prompt, and you never find out what the prompt was missing.

Mistakes are cheap. Luna is the low-cost model of its series, so a failed run costs the school little and costs you nothing. Break things on purpose and watch the gate turn red. Then you run it again. Much of this course is exactly that.

2.4 What you need on your machine

Docker with Compose. On Windows and macOS, install Docker Desktop, which brings Compose with it. On Linux, install the Docker engine plus the Compose plugin from your distribution or from Docker’s own repository.

Visual Studio Code (VS Code). You attach it to the running container and work inside that container’s terminal. Nothing in this course installs .NET, Node.js, or PostgreSQL on your own machine.

You have learned about Docker and VS Code fundamentals in other courses. If you struggle, ask your teacher or an AI. Figuring out how to work with the course material is part of the exercise.

2.5 The project folder from your teacher

Your teacher hands you a folder with four files and one subfolder in it. You do not have to write any of them.

  • compose.yaml defines the two services you work with, the development container and a PostgreSQL database.
  • Dockerfile builds the development container, with .NET 10, Node.js, the Angular CLI, git, the PostgreSQL client, and pi already installed.
  • models.json tells pi which model to talk to, where that model is hosted, and how much room it gets. The chapter “Meet pi” reads those numbers with you.
  • auth.json.example shows the shape of the credential file, with a placeholder where your own key goes.
  • skill-source/ holds the custom skills for this course. The container sees it read-only as ~/skill-source, and the chapter “The cutoff problem” installs the skills from there into your project.

pi reads auth.json, not the example. That file is missing on purpose, because the key in it is yours alone. The next section gets you that key and turns the example into the real file.

2.6 Pick up your key

The model endpoint is a Novedu coding activity, and you fetch your own key from that activity’s page.

Your coding agent

Sign in with your school account and the page gives you a key of your own. That key is what your coding tool needs. The code below opens the page and nothing else.

Your teacher sees that you asked for a key, never what you ask the agent.

▶ Get your coding key on app.novedu.at

The page also names a server address and a model, and you already have both in the models.json from your teacher. So the key is the only thing you take away from it. In the folder your teacher gave you, copy the example file:

cp auth.json.example auth.json

Then open auth.json and paste the key in place of the placeholder:

{
  "novedu": {
    "type": "api_key",
    "key": "nvk-your-own-key-goes-here"
  }
}

Every key starts with nvk-, so a value in a different shape is the wrong string.

The key is yours

Treat the key like a password. Do not post it anywhere, and never commit auth.json to a repository you push. Nobody else in the class has your key, so a key that turns up somewhere else came from you. Opening the page a second time hands you the same key back, so there is nothing to lose and nothing to rotate.

If you are not a student with access to Novedu, you can still take the course. Point pi at GPT-6 Luna through your own OpenRouter account, or at any other model you have access to.
