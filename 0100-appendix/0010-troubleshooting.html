Appendix A — Troubleshooting

Something will misbehave. When it does, look for the symptom in the left column before you read your own code. Almost everything that breaks in this course is a harness problem, not a code problem: an extension never loaded, a stopped container, a trust prompt nobody accepted. The application code is usually fine. You fix the harness around it.

Symptom Cause and fix
pi reports an authentication error auth.json next to compose.yaml is missing, is malformed, or holds the activity code instead of your key. A key starts with nvk-. Check the JSON shape against the example in the “Your toolkit” chapter, and open the activity page again to read your key. The page always hands back the same one, so a key that stops working means your teacher closed the activity.
pi fails with a confusing configuration error on first start auth.json did not exist when the container first started, so Docker created a directory under that name. On your host, in the folder that holds compose.yaml: docker compose down, delete the auth.json directory, run cp auth.json.example auth.json and paste your key in, then docker compose up -d.
pi will not start, and node reports an error about a bootloader script VS Code’s JavaScript auto-attach sets NODE_OPTIONS=--require .../bootloader.js in the terminals it opens, and pi fails to start with it. Run unset NODE_OPTIONS in that terminal, then start pi again. Auto-attach is a setting in your own VS Code rather than something in the container, so turn it off with the command Debug: Toggle Auto Attach if it keeps coming back.
Agent does not know about microsoft-docs The project is not trusted. Restart pi and accept the trust prompt, or start it with pi -a.
ls ~/skill-source prints nothing The skill-source/ folder was not next to compose.yaml when the container started, so Docker mounted an empty directory instead. Put the folder from your teacher back next to compose.yaml, then run docker compose up -d again
dotnet test rejects a flag such as --nologo xUnit v3 runs on the Microsoft Testing Platform, which refuses some flags the older VSTest runner accepted. Current packages work this way by design, so your code is not the problem. Let the agent read the error and adjust the test invocation in the gate script.
dotnet format fails on files under the migrations folder The EF Core migration generator writes files the formatter and analyzers dislike, starting with a byte order mark. Add a scoped .editorconfig section for the migrations folder. Check that the scope covers that folder and nothing more. See the “The harness pays off” chapter.
Build warning MSB3277 (conflicting assembly versions) in the test project The Npgsql provider’s dependency ranges can pull different versions into the API and test projects. TreatWarningsAsErrors turns that warning into a red gate. Let the agent align the package versions across both projects.
The gate never runs by itself The extension has to exist before the session starts, so the session that wrote it never loaded it. Restart pi or run /reload. Then check the timestamp on quality-gate.log after the next turn.
The gate still never runs after a restart Project-local extensions only load in a trusted project, and only from .pi/extensions/. Accept the trust prompt or start with pi -a. Then check where the file landed.
The gate goes red and the agent stops anyway The extension is listening on agent_settled instead of agent_end. A message on agent_settled never starts a new turn. See the “Automate the gate” chapter.
npx @microsoft/learn-cli is slow the first time The first call downloads the package. Later calls use the cache.
Agent runs out of context while reading quality-gate.log The log gets long. Tell the agent to read only the tail, or make the gate script log a summary.
A run went badly wrong Run git checkout . and git clean -fd, then rephrase the prompt. Resetting is cheaper than arguing with the agent.
Gate red with NpgsqlException The db container is not running. Run docker compose start db on your host.
dotnet ef not found Rebuild the container with docker compose build dev. Or let the agent add a local tool manifest and run dotnet tool restore.
Integration tests fail only in a full run They assume an empty database, and they share that database with the app. See the “Integration tests” chapter.
pi prints nothing for several minutes A request to the shared endpoint was lost. Abort and send the same prompt again. It usually succeeds. Run only one pi session at a time, because concurrent sessions lose requests more often.
This extension ctx is stale after session replacement or reload, and pi dies The gate extension’s agent_end handler returns before it has sent its message, so the gate talks to a session that has already been replaced. The handler has to await the gate and send the message before returning. See the “Automate the gate” chapter.
The agent keeps retrying a gate it cannot fix Nothing limits the number of retries, and the gate stays red for a reason outside the code. Limit the consecutive retries. See the “Close the loop” chapter.
Author identity unknown when the agent commits You never set git config user.name and git config user.email. See the “Git is your undo button” chapter.
Playwright says “port is already used” A previous run ended without releasing the port. Run pkill -f 'ng serve' and pkill -f 'backend/Calculator.Api'.
Agent uses up its context on documentation The angular-developer skill ships 40 reference files. Tell the agent to read only what it needs.
~/work is empty and everything is gone Somebody ran docker compose down -v, which deletes the work_data volume that holds it. Plain docker compose down and a rebuild both keep it. See the note in the “Git is your undo button” chapter.
The API responds inside the container, but your browser cannot reach port 5074 Check whether the API listens only on the container’s loopback address. Ask the agent to set applicationUrl to http://0.0.0.0:5074 in the launchSettings.json profile used by dotnet run. Restart the API and retry from your browser. compose.yaml already publishes port 5074.
Browser cannot reach the app’s port compose.yaml publishes only ports 4200 and 5074. For any other port, use the VS Code Ports panel in the attached window to forward it.
git checkout . did not undo the run git checkout . only reverts tracked files. The agent’s new files stay until you run git clean -fd.
